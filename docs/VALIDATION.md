该仓库主线来自UART低延迟版本，不是V4。软件实现与用户指定固件对应；此整理过程没有修改无线、DAP、UART或板级生产源码。

## 本次独立目录验证

- 在此仓库根目录执行 `build.ps1`，无需原开发工程的vendor、variant或其他版本目录。
- Adafruit nRF52 Core1.7.0 / Arduino CLI1.5.1 / 固定原构建参数。
- 程序90,656字节、静态RAM60,560字节；UF2 181,760字节，355块，0x26000..0x3C300。
- 重建固件SHA256：`7E3C4C9DACCF2E4EE8F4F7374D04B86C9DC7B918FE94259589ED8AC29D928147`。
- 与原指定UF2逐字节一致，不仅文件名一致。
- 自由角色、DAP128 USB组包/响应、断链恢复、UART延迟/重试/顺序/背压、UART策略时序测试通过。
- 真实RADIO状态机1,000组随机双向交换模型通过，覆盖丢ACK、CRC、去重、背压、旧启动标识、取消、包长与计时回绕。
- 将测试模拟头文件对原工程目录的依赖改为本仓库内文件；去掉与当前USB状态机/API不匹配的历史测试，以及8MHz实验测试。

`role_test.cpp` 是各测试包含的模拟应用夹具，不能单独当作自由角色验收程序执行。运行根目录run_tests.ps1即可。

`source-manifest.json`记录生产源码与原参考固件的身份，`python tools/verify_source.py`用于核对这个初始快照。后续修改源码后需更新清单或明确记录新的版本，而不是期望继续匹配旧哈希。

## 实板证据边界

原交接记录把本低延迟固件标为已构建、桌面测试通过的候选，尚无它的实板端到端延迟/长期稳定验收统计。本次仅整理源码并构建/模拟，没有刷板、访问DAP/COM或操作目标。

1ms合包、20ms首次补发是模型/调度策略，不是主机到UART的真实延迟。波特率设置支持不等于每个档位已实测通过；没有RTS/CTS与持续满速无损承诺。实际烧录耗时、射频距离和故障恢复须按USAGE.md在两板及目标上验证。
